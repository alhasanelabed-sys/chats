# مجلس — نموذج تطبيق أندرويد للاجتماعات

تطبيق عربي أصلي يسجّل اجتماعًا، ويحفظه محليًا، ثم يرسل التسجيل بعد تأكيد واضح إلى خادم معالجة لإعداد نص حسب المتحدثين ومحضر وملخص. بُني ملف APK تجريبي وجرى التحقق من توقيعه في GitHub Actions. لم يُختبر الصوت على هاتف حقيقي أو اتصال OpenAI الحقيقي بعد.

## تنزيل ملف التثبيت

[تنزيل majlis-debug.apk مباشرة](https://github.com/alhasanelabed-sys/chats/raw/refs/heads/app/majlis-android/downloads/majlis-debug.apk). هذا رابط عام لملف APK داخل فرع التطبيق، ولا يحتاج تسجيل الدخول إلى GitHub. ثبّت الملف على هاتف أندرويد 8.0 فأحدث. يمكن تجربة الاجتماع الجاهز وتسجيل الصوت دون إعداد الخادم؛ التحليل الحقيقي يحتاج إعداد الخدمة الموضح أدناه. يحتفظ فرع التطبيق بملف التثبيت، بينما تبقى نسخ GitHub Actions الإضافية متاحة 14 يومًا وتتطلب تسجيل الدخول.

## وظائف النموذج

- واجهة عربية من اليمين إلى اليسار، وتسجيل AAC/M4A فعلي بحد أقصى 20 دقيقة.
- تسجيل ظاهر بإشعار يتيح الإيقاف، ويستمر عند قفل الشاشة. في أندرويد 13 فأحدث يُطلب إذن الإشعارات.
- تسجيل عينة مدتها 5 ثوانٍ باسم كل مشارك، بموافقته، حتى أربعة مراجع صوتية. العينة محفوظة على الجهاز؛ لا توجد قاعدة بيانات بصمات بيومترية.
- بعد انتهاء التسجيل: تفريغ عربي وفصل المتحدثين، وربط الاسم بالعينة إذا طابقها النموذج. الأصوات الأخرى تُرقّم ويمكن تصحيح أسمائها، بما فيها من تكلم بعد انضمامه لاحقًا.
- ملخص، نقاط نقاش، قرارات، مهام ومسؤولون ومواعيد إن وردت، وأسئلة مفتوحة. لكل قرار ومهمة مراجع إلى مقاطع النص.
- تعديل اسم المتحدث، وحفظ المحاضر محليًا، وحذفها مع تسجيلها، ومشاركة المحضر والنص.
- اجتماع تجريبي معلّم بوضوح يمكن عرضه دون خادم أو اتصال أو مفتاح خدمة. محتواه مثال، وليس تحليلًا لتسجيل المستخدم.

فصل المتحدثين والتعرف على الاسم يجريان بعد انتهاء التسجيل، ولا يعرض النموذج تفريغًا أو مطابقة أصوات لحظية. الاسم الحقيقي لا يُستنتج من صوت مجهول؛ يدخله المستخدم مع العينة أو يصححه بعد التحليل. جودة التسجيل تتأثر بالمسافة والضوضاء والتداخل؛ استخدم ميكروفون اجتماعات للغرف الكبيرة. مراجعة المحضر مطلوبة قبل اعتماده.

## بناء تطبيق أندرويد

يتطلب Android 8.0 فأحدث (API 26). مشروع Android Studio موجود في `android/`، دون مكتبات أندرويد إضافية.

1. افتح مجلد `android` في Android Studio.
2. ثبّت Android SDK Platform 35 وBuild Tools 35.0.0، واسمح باستكمال اعتماديات Gradle.
3. ابنِ `app` بصيغة Debug، ثم ثبّته على هاتفك أو المحاكي.

يوجد مسار بناء من سطر الأوامر باستخدام SDK مثبت محليًا، موضح في `scripts/build-android.sh`. يكتب APK في `dist/majlis-debug.apk`. النسخة التجريبية تستخدم مفتاح debug محليًا، وليست إصدارًا للنشر في Google Play. أدوات SDK ومفاتيح توقيع debug لا تدخل في حزمة المصدر.

على فرع `app/majlis-android` يشغّل GitHub Actions بناء أندرويد واختبارات الخادم تلقائيًا. بعد نجاح مهمة `android` يحفظ ملف APK في `downloads/majlis-debug.apk` على فرع التطبيق، ويتيح أيضًا نسخة مضغوطة باسم `majlis-debug-apk` في قسم Artifacts. لا تتطلب اختبارات الخادم أو بناء APK مفتاح OpenAI. يحتفظ Actions بملف التثبيت مدة 14 يومًا.

## إعداد التحليل الحقيقي

اتبع [دليل الخادم](backend/README.md) لتشغيله. يتطلب Python وFFmpeg ومفتاح OpenAI متاحًا لصاحب الخادم، ورمز وصول خاصًا. المفتاح يبقى على الخادم؛ لا يُوضع داخل التطبيق. قد تحتسب خدمة الذكاء الاصطناعي رسومًا على حساب صاحب المفتاح.

في إعدادات التطبيق أدخل رابط HTTPS للخادم ورمز `MAJLIS_ACCESS_TOKEN`. على محاكي أندرويد، إذا كان الخادم على الحاسوب المضيف، استخدم `http://10.0.2.2:8000`. على هاتف حقيقي استخدم رابط HTTPS يمكن للهاتف الوصول إليه. لم يُنشر خادم عام ضمن هذا المشروع.

أضف عينات المشاركين من تبويب الأصوات، وأعلم الحاضرين بالتسجيل، ثم ابدأ الاجتماع. بعد الإنهاء اضغط «إعداد المحضر والملخص». يظهر تأكيد يوضح إرسال تسجيل الاجتماع والعينات إلى الخادم وOpenAI. قبول التسجيل لا يؤدي إلى رفع تلقائي.

حذف عينة في التطبيق يحذف ملفها المحلي، وحذف اجتماع يحذف المحضر والصوت المرتبط. يوقف النموذج التسجيل المنقطع ويمنع عرضه كملف مكتمل بعد فقد العملية. لا يبدأ الميكروفون تلقائيًا بعد إعادة تشغيل التطبيق. النسخ الاحتياطي التلقائي معطل. يخزن رمز الخادم في إعدادات التطبيق الخاصة؛ هذه نسخة أولية لمستخدم خاص.

## التحقق وحدوده

```bash
cd backend
python -m unittest discover -s tests -v
python -m compileall -q app tests
```

اجتاز الخادم 21 اختبارًا باستخدام ملفات M4A حقيقية مولدة ببرنامج FFmpeg، ومحاكاة مزود الخدمة عند حد HTTP فقط. تشمل مصادقة الرفع وحجم الرفع والمدة والعينات وإضافة متحدث جديد والأدلة وتنظيف الملفات. لا تثبت هذه الاختبارات دقة النموذج في غرفة فعلية.

ملفات أندرويد راجعتها مراجعة مستقلة لحالات الإيقاف والاستئناف وأذونات الميكروفون والإشعارات، وحفظ الملفات وتعديل الأسماء. نجح تجميع موارد التطبيق وJava وتحويل D8 والتحقق من توقيع APK على GitHub Actions في [التشغيل 37980802110](https://github.com/alhasanelabed-sys/chats/actions/runs/37980802110)، ونجحت اختبارات الخادم في التشغيل نفسه. تعذر البناء المحلي بسبب عدم توفر SDK واتصال وكيل الشبكة، فجرى البناء في GitHub بدلًا منه. يلزم اختبار على هاتف: بدء تسجيل وإيقافه، قفل الشاشة، إذن ميكروفون مرفوض، عينة 5 ثوانٍ، انقطاع العملية، رفع تسجيل بموافقة المشاركين، مراجعة الأسماء، وحذف ومشاركة المحضر.

## ملفات المشروع

`android/`: التطبيق الأصلي. `backend/`: خدمة المعالجة واختباراتها. `scripts/`: بناء التطبيق وفحص أدوات SDK. `dist/`: مخرجات المصدر والبناء. لا توجد مفاتيح خدمة أو حسابات جاهزة في المشروع.
