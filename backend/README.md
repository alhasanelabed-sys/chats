# خادم «مجلس» للنموذج الأولي

يستقبل تسجيل Android أو ملفا مستوردا بصيغة M4A أو MP3 أو WAV بعد موافقة المستخدم على الإرسال، ويفرغ الكلام بالعربية مع فصل المتحدثين، ثم يعد مسودة محضر وملخص وقرارات ومهام مرتبطة بمقاطع التسجيل. الإصدار 0.2 يتيح أيضا إعداد محضر جديد من النص والأسماء بعد تصحيحها، دون إعادة إرسال الصوت أو إعادة تفريغه.

الخادم يستخدم `gpt-4o-transcribe-diarize` للتفريغ وفصل المتحدثين، و`gpt-4.1-mini` لإعداد المحضر. يلزم مفتاح OpenAI فعال وصلاحية استخدام النموذجين، وتطبق رسوم المزود. لا يوجد مفتاح خدمة داخل APK. وضع العرض التجريبي في التطبيق يعمل دون هذا الخادم، ويعرض بيانات مثال معلنة بوضوح.

## التشغيل

يتطلب Python 3.12+ وFFmpeg الذي يوفر الأمرين `ffprobe` و`ffmpeg`. يعمل على Linux أو macOS أو Windows بعد تثبيت هذين المتطلبين.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

عدّل `.env` محليا وأدخل مفتاحك ورمز وصول عشوائيا، ثم شغّل:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000 --env-file .env
```

تتضمن المتطلبات `python-dotenv` لاستعمال `--env-file`؛ يمكن بدلا من ذلك ضبط متغيرات البيئة في نظام التشغيل وتشغيل Uvicorn دون هذا الخيار. في PowerShell استخدم `.venv\Scripts\Activate.ps1` للتفعيل. لا يطبع الخادم قيم الأسرار عند نقص الإعدادات؛ يفشل التشغيل بأسماء المتغيرات المفقودة.

ولإنشاء رمز وصول محلي:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

أدخل عنوان HTTPS للخادم ورمز `MAJLIS_ACCESS_TOKEN` في إعدادات تطبيق Android. يحتاج الهاتف إلى عنوان يمكنه الوصول إليه؛ `127.0.0.1` على الهاتف يشير إلى الهاتف نفسه. نشر خادم HTTPS وتشغيله العام يحتاجان استضافة وإعدادا منفصلين، ولم ينشرا ضمن هذا النموذج. لمشاركة نسخة الخادم مع الهاتف استخدم خدمة HTTPS موثوقة أو reverse proxy مع شهادة صالحة، وزد مهلة طلب التحليل إلى عشر دقائق على الأقل. لا تُدخل `OPENAI_API_KEY` في الهاتف.

لبيئة خدمة عامة يلزم تقييد الطلبات والمستخدمين والتوازي والتكلفة عند reverse proxy؛ رمز الوصول المشترك الحالي مخصص لنموذج أولي خاص. اضبط حدا لحجم الطلب يبلغ `28,100,000` بايت أو أقل، ولا تسجل أجسام الطلبات أو رؤوس Authorization. استخدم قرصا مؤقتا مشفرا عند التعامل مع تسجيلات حساسة.

## العقد مع تطبيق Android

- `GET /health` يعيد `{"status":"ok"}` ولا يعرض إعدادات أو أسرارا.
- `GET /v1/status` يتطلب رمز الوصول نفسه، ويعيد `{"status":"ok","version":"0.2","max_audio_bytes":24000000,"max_duration_seconds":3600,"formats":["m4a","mp3","wav"],"reference_speakers":4}`. يستخدمه التطبيق للتحقق من عنوان الخدمة وصحة الرمز وتوافق الإصدار؛ لا يرسل طلبا مدفوعا للمزود ولا يضمن توافر رصيد أو صلاحية مفتاح المزود.
- `POST /v1/meetings/analyze` يتطلب `Authorization: Bearer <MAJLIS_ACCESS_TOKEN>`.
- يرسل `multipart/form-data` وفيه `audio` ملف M4A أو MP3 أو WAV و`title` عنوان بطول 1–160 حرفا و`participants` نص JSON لقائمة المشاركين. يمكن إرسال قائمة فارغة `[]`.
- بنية المشارك: `{"id":"p_1","name":"سارة","reference_field":"reference_0"}`. `reference_field` اختياري؛ يرسل كل ملف عينة باسم الحقل المشار إليه.
- يقبل الخادم أربع عينات مسماة بحد أقصى، بأسماء الحقول `reference_0` حتى `reference_3`، ومدة كل عينة 2–10 ثوان وبصيغة M4A حصرا؛ يسجل التطبيق خمس ثوان لكل عينة. تبقى بايتات العينات كما أرسلها التطبيق.
- الحد الأقصى لملف الاجتماع `24,000,000` بايت، ولكل عينة `1,000,000` بايت، وللطلب كله `28,100,000` بايت، ومدة الاجتماع في الخادم 60 دقيقة. تطبيق Android 0.2 يسجل AAC بمعدل 48 kbps وقناة واحدة و32 kHz لمدة تصل إلى ساعة ليبقى عادة ضمن حد الحجم. تعالج الملفات كاملة في طلب واحد؛ لا يوجد تقسيم تلقائي لملف أكبر من الحد. قد يبلغ ملف WAV حد الحجم قبل ساعة بسبب الصوت غير المضغوط.
- يتحقق الخادم من توقيع الملف ومحتواه ووجود صوت ومدة فعلية عبر `ffprobe` قبل فك الصوت. يتجاهل الامتداد وMIME عند التحقق، ويرفض الفيديو والوسائط غير المدعومة والملفات التالفة وقوائم التشغيل والحقول المكررة والمجهولة. يقتصر FFmpeg على بروتوكولي الملفات المحلية والأنابيب مع اختيار قارئ صيغة ثابت؛ لا يفتح روابط وسائط من الشبكة.
- يحول ملف الاجتماع إلى M4A صوتي بقناة واحدة وAAC 48 kbps و32 kHz قبل إرساله للمزود، مع حد مستقل للحجم الناتج والمدة ومهلة تهيئة 180 ثانية. يوقف العملية ويحذف الملف الجزئي عند انتهاء المهلة أو إلغاء الطلب. هذه التهيئة لتوحيد صيغة الرفع وحجمه؛ لا تعني زيادة مثبتة في دقة التعرف أو تحسين صوت لم يلتقطه الميكروفون.

مثال طلب محلي، بعد ضبط متغير البيئة للرمز:

```bash
curl http://127.0.0.1:8000/v1/meetings/analyze \
  -H "Authorization: Bearer $MAJLIS_ACCESS_TOKEN" \
  -F 'title=اجتماع الفريق' \
  -F 'participants=[{"id":"p_1","name":"سارة","reference_field":"reference_0"}]' \
  -F 'audio=@meeting.m4a;type=audio/mp4' \
  -F 'reference_0=@sara.m4a;type=audio/mp4'
```

النتيجة:

```json
{
  "title": "اجتماع الفريق",
  "language": "ar",
  "duration_seconds": 60.0,
  "segments": [
    {"id": "seg_0", "speaker_id": "known_0", "start": 0.0, "end": 2.0, "text": "سنعتمد الميزانية."}
  ],
  "speakers": [
    {"id": "known_0", "name": "سارة", "matched_reference": true}
  ],
  "minutes": {
    "summary": "ناقش الحضور الميزانية.",
    "discussion_points": ["الميزانية"],
    "decisions": [{"text": "اعتماد الميزانية", "segment_ids": ["seg_0"]}],
    "action_items": [],
    "open_questions": []
  }
}
```

هذا المثال يشرح شكل البيانات فقط، وليس نتيجة تسجيل حقيقي. يتبع `speaker_id` معرف المزود داخل الاجتماع، مثل `known_0` أو `A` أو `B`؛ لا يعد معرفا ثابتا للشخص عبر الاجتماعات. يربط الخادم الاسم المدخل بعينة فقط عندما يعيد مزود فصل المتحدثين معرف تلك العينة. المشاركون دون عينات لا تنسب إليهم أسماء تلقائيا. أي صوت جديد يمكن سماعه في التسجيل، بما فيه من دخل لاحقا، يظهر كمتحدث إضافي إذا فصله النموذج. الأسماء العامة هي «متحدث 1» و«متحدث 2» حسب أول ظهور، ويستطيع المستخدم تصحيحها في التطبيق.

## إعادة إعداد المحضر بعد تصحيح النص

`POST /v1/meetings/summarize` يتطلب رمز الوصول نفسه و`Content-Type: application/json`. يعرض التطبيق موافقة منفصلة قبل إرسال النص المصحح والأسماء. يرسل الحقول `title` و`language` بقيمة `ar` و`duration_seconds` و`segments` و`speakers` بنفس بنيتها في النتيجة أعلاه، ويحذف `minutes`؛ لا يرسل صوتا أو عينات. يعيد الخادم `MeetingAnalysis` بنفس النص والأسماء مع محضر جديد، ويستخدم نموذج إعداد المحضر فقط دون نموذج التفريغ.

الحد الأقصى للطلب `2,000,000` بايت، وتطبق مراقبة البايتات الفعلية حتى عند الرفع المجزأ. يقبل حتى 2000 مقطع و128 متحدثا، و20,000 حرف للمقطع و300,000 حرف للنص كله. يلزم عنوان غير فارغ بطول حتى 160 حرفا وأسماء غير فارغة حتى 80 حرفا ومعرفات غير فارغة وفريدة. يرفض معرف متحدث مجهولا أو كلاما فارغا أو توقيتات غير محدودة أو سالبة أو معكوسة. يسمح بانتهاء آخر مقطع حتى ثانية واحدة بعد مدة الملف لمواءمة تقريب توقيتات المزود في التحليل الأول، ويحافظ على التوقيتات نفسها عند إعادة المحضر؛ يرفض ما يتجاوز هذا الهامش. يمكن أن تكون قائمتا المقاطع والمتحدثين فارغتين معا للتعبير عن عدم وجود كلام مفيد؛ يعيد الخادم محضرا يوضح ذلك دون الاتصال بالمزود.

تظل أسماء المتحدثين والمقاطع والعنوان بيانات غير موثوقة في تعليمات النموذج، وتطبق ضوابط `segment_ids` نفسها على المحضر الجديد. لا يجري الخادم إثباتا دلاليا آليا لكل حقيقة في النص؛ يلزم مراجعة المحضر الناتج قبل اعتماده. تصحيح الاسم يدويا لا يثبت هوية صاحبه.

`matched_reference` يعني أن نموذج فصل المتحدثين طابق العينة، ولا يمثل مصادقة هوية أو ضمانا بيومتريا. المسافة والضوضاء والكلام المتداخل قد تسبب حذف كلام أو أخطاء في الفصل أو المطابقة. لا يستعيد النظام صوتا لم يلتقطه ميكروفون الهاتف. ضع الهاتف قريبا من الحاضرين، أو استخدم ميكروفونا خارجيا للاجتماعات الكبيرة.

`segment_ids` روابط إلى المقاطع التي تدعم القرار أو المهمة. يرفض الخادم أي مراجع لمقاطع غير موجودة أو فارغة. يطلب من النموذج تجنب المهام والقرارات المخترعة، ووضع `owner` و`due_date` بقيمة `null` عند عدم التصريح بهما. يحتفظ بالموعد النسبي كما قيل دون اختراع تاريخ تقويمي. تبقى صحة المحتوى الذي كتبه النموذج بحاجة إلى مراجعة بشرية قبل اعتماد المحضر.

## البيانات والأخطاء

يستخدم الخادم ملفات مؤقتة لحين انتهاء الطلب، ويحذفها عند النجاح والخطأ والإلغاء العادي. لا توجد قاعدة بيانات أو حفظ للصوت أو التفريغ، ولا تسجيل للمحتوى في الشيفرة. قد تبقى ملفات مؤقتة إذا توقفت العملية بالقوة أو توقف نظام التشغيل؛ نظف مساحة الملفات المؤقتة دوريا. ينتقل التسجيل المهيأ والعينات إلى OpenAI، ثم ينتقل التفريغ والأسماء المطابقة إلى نموذج إعداد المحضر. عند إعادة إعداد المحضر ينتقل النص المصحح والأسماء فقط. يرسل `store:false` لطلب Responses؛ قواعد الاحتفاظ بالبيانات لدى المزود تبقى خاضعة لإعدادات حسابك وسياساته. تأكد من موافقة المشاركين واعرض إشعار الإرسال قبل التحليل وقبل إعادة إعداد المحضر.

رموز الأخطاء: `401` رمز وصول غير صالح؛ `413` حجم زائد؛ `422` بيانات أو صوت غير صالحين؛ `502` تعذر اتصال الخدمة أو نتيجة مزود غير صالحة. لا تعاد رسائل المزود الخام التي قد تكشف معلومات حساسة. لا تعاد محاولة آلية قد تضاعف تكلفة طلب مدفوع؛ يمكن للمستخدم المحاولة مجددا بعد التحقق من المشكلة.

## التحقق

```bash
python -m unittest discover -s tests -v
python -m compileall -q app tests
```

تستخدم الاختبارات M4A وMP3 وWAV حقيقية مولدة بـFFmpeg للتحقق من مسار الرفع وفحص الصوت وتهيئة AAC، و`httpx.MockTransport` عند حدود خدمة OpenAI. لا تحتاج إلى مفاتيح فعلية ولا ترسل صوتا إلى الشبكة. تشمل المصادقة ونقص الإعدادات وحجم الطلب والوسائط المصورة والتالفة وغير المدعومة وأسماء العينات والمتحدث الجديد وإسناد الأدلة ونتائج المزود التالفة، وإعادة المحضر من النص المصحح، وحدود النص والرفع المجزأ وتنظيف عملية التهيئة عند المهلة والإلغاء. لا تقيس هذه الاختبارات جودة التعرف على العربية أو بصمة الصوت؛ ذلك يحتاج تجربة حقيقية بملفات وافق أصحابها على استخدامها وحساب مزود فعال.

عقد الخدمة مستند إلى تعريفات SDK الرسمية التي روجعت أثناء بناء النموذج: [طلب التفريغ](https://github.com/openai/openai-python/blob/main/src/openai/types/audio/transcription_create_params.py)، [مقطع فصل المتحدثين](https://github.com/openai/openai-python/blob/main/src/openai/types/audio/transcription_diarized_segment.py)، [دليل التفريغ الصوتي](https://developers.openai.com/api/docs/guides/speech-to-text).
