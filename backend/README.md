# خادم «مجلس» للنموذج الأولي

يستقبل تسجيل Android بصيغة M4A بعد موافقة المستخدم على الإرسال، ويفرغ الكلام بالعربية مع فصل المتحدثين، ثم يعد مسودة محضر وملخص وقرارات ومهام مرتبطة بمقاطع التسجيل.

الخادم يستخدم `gpt-4o-transcribe-diarize` للتفريغ وفصل المتحدثين، و`gpt-4.1-mini` لإعداد المحضر. يلزم مفتاح OpenAI فعال وصلاحية استخدام النموذجين، وتطبق رسوم المزود. لا يوجد مفتاح خدمة داخل APK. وضع العرض التجريبي في التطبيق يعمل دون هذا الخادم، ويعرض بيانات مثال معلنة بوضوح.

## التشغيل

يتطلب Python 3.12+ وFFmpeg الذي يوفر الأمر `ffprobe`. يعمل على Linux أو macOS أو Windows بعد تثبيت هذين المتطلبين.

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

عدّل `.env` محليا وأدخل مفتاحك ورمز وصول عشوائيا، ثم شغّل:

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000 --env-file .env
```

تتضمن المتطلبات `python-dotenv` لاستعمال `--env-file`؛ يمكن بدلا من ذلك ضبط متغيرات البيئة في نظام التشغيل وتشغيل Uvicorn دون هذا الخيار. في PowerShell استخدم `.venv\Scripts\Activate.ps1` للتفعيل. لا يطبع الخادم قيم الأسرار عند نقص الإعدادات؛ يفشل التشغيل بأسماء المتغيرات المفقودة.

ولإنشاء رمز وصول محلي:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

أدخل عنوان HTTPS للخادم ورمز `MAJLIS_ACCESS_TOKEN` في إعدادات تطبيق Android. يحتاج الهاتف إلى عنوان يمكنه الوصول إليه؛ `127.0.0.1` على الهاتف يشير إلى الهاتف نفسه. نشر خادم HTTPS وتشغيله العام يحتاجان استضافة وإعدادا منفصلين، ولم ينشرا ضمن هذا النموذج. لمشاركة نسخة الخادم مع الهاتف استخدم خدمة HTTPS موثوقة أو reverse proxy مع شهادة صالحة، وزد مهلة طلب التحليل إلى عشر دقائق على الأقل. لا تُدخل `OPENAI_API_KEY` في الهاتف.

لبيئة خدمة عامة يلزم تقييد الطلبات والمستخدمين والتوازي والتكلفة عند reverse proxy؛ رمز الوصول المشترك الحالي مخصص لنموذج أولي خاص. اضبط حدا لحجم الطلب يبلغ `28,100,000` بايت أو أقل، ولا تسجل أجسام الطلبات أو رؤوس Authorization. استخدم قرصا مؤقتا مشفرا عند التعامل مع تسجيلات حساسة.

## العقد مع تطبيق Android

- `GET /health` يعيد `{"status":"ok"}` ولا يعرض إعدادات أو أسرارا.
- `POST /v1/meetings/analyze` يتطلب `Authorization: Bearer <MAJLIS_ACCESS_TOKEN>`.
- يرسل `multipart/form-data` وفيه `audio` ملف M4A و`title` عنوان بطول 1–160 حرفا و`participants` نص JSON لقائمة المشاركين. يمكن إرسال قائمة فارغة `[]`.
- بنية المشارك: `{"id":"p_1","name":"سارة","reference_field":"reference_0"}`. `reference_field` اختياري؛ يرسل كل ملف عينة باسم الحقل المشار إليه.
- يقبل الخادم أربع عينات مسماة بحد أقصى، بأسماء الحقول `reference_0` حتى `reference_3`، ومدة كل عينة 2–10 ثوان؛ يسجل التطبيق خمس ثوان لكل عينة.
- الحد الأقصى لملف الاجتماع `24,000,000` بايت، ولكل عينة `1,000,000` بايت، وللطلب كله `28,100,000` بايت، ومدة الاجتماع في الخادم 60 دقيقة. تطبيق Android يحدد التسجيل بـ20 دقيقة وAAC 128 kbps ليبقى عادة ضمن حد الحجم. تعالج الملفات كاملة في طلب واحد؛ لا يوجد تقسيم تلقائي لملف أكبر من الحد.
- يتحقق الخادم من محتوى M4A ووجود صوت ومدة فعلية عبر `ffprobe` قبل طلب الخدمة. يرفض الملفات المصورة أو التالفة والحقول المكررة والمجهولة.

مثال طلب محلي، بعد ضبط متغير البيئة للرمز:

```bash
curl http://127.0.0.1:8000/v1/meetings/analyze \
  -H "Authorization: Bearer $MAJLIS_ACCESS_TOKEN" \
  -F 'title=اجتماع الفريق' \
  -F 'participants=[{"id":"p_1","name":"سارة","reference_field":"reference_0"}]' \
  -F 'audio=@meeting.m4a;type=audio/mp4' \
  -F 'reference_0=@sara.m4a;type=audio/mp4'
```

النتيجة:

```json
{
  "title": "اجتماع الفريق",
  "language": "ar",
  "duration_seconds": 60.0,
  "segments": [
    {"id": "seg_0", "speaker_id": "known_0", "start": 0.0, "end": 2.0, "text": "سنعتمد الميزانية."}
  ],
  "speakers": [
    {"id": "known_0", "name": "سارة", "matched_reference": true}
  ],
  "minutes": {
    "summary": "ناقش الحضور الميزانية.",
    "discussion_points": ["الميزانية"],
    "decisions": [{"text": "اعتماد الميزانية", "segment_ids": ["seg_0"]}],
    "action_items": [],
    "open_questions": []
  }
}
```

هذا المثال يشرح شكل البيانات فقط، وليس نتيجة تسجيل حقيقي. يتبع `speaker_id` معرف المزود داخل الاجتماع، مثل `known_0` أو `A` أو `B`؛ لا يعد معرفا ثابتا للشخص عبر الاجتماعات. يربط الخادم الاسم المدخل بعينة فقط عندما يعيد مزود فصل المتحدثين معرف تلك العينة. المشاركون دون عينات لا تنسب إليهم أسماء تلقائيا. أي صوت جديد يمكن سماعه في التسجيل، بما فيه من دخل لاحقا، يظهر كمتحدث إضافي إذا فصله النموذج. الأسماء العامة هي «متحدث 1» و«متحدث 2» حسب أول ظهور، ويستطيع المستخدم تصحيحها في التطبيق.

`matched_reference` يعني أن نموذج فصل المتحدثين طابق العينة، ولا يمثل مصادقة هوية أو ضمانا بيومتريا. المسافة والضوضاء والكلام المتداخل قد تسبب حذف كلام أو أخطاء في الفصل أو المطابقة. لا يستعيد النظام صوتا لم يلتقطه ميكروفون الهاتف. ضع الهاتف قريبا من الحاضرين، أو استخدم ميكروفونا خارجيا للاجتماعات الكبيرة.

`segment_ids` روابط إلى المقاطع التي تدعم القرار أو المهمة. يرفض الخادم أي مراجع لمقاطع غير موجودة أو فارغة. يطلب من النموذج تجنب المهام والقرارات المخترعة، ووضع `owner` و`due_date` بقيمة `null` عند عدم التصريح بهما. يحتفظ بالموعد النسبي كما قيل دون اختراع تاريخ تقويمي. تبقى صحة المحتوى الذي كتبه النموذج بحاجة إلى مراجعة بشرية قبل اعتماد المحضر.

## البيانات والأخطاء

يستخدم الخادم ملفات مؤقتة لحين انتهاء الطلب، ويحذفها عند النجاح والخطأ والإلغاء العادي. لا توجد قاعدة بيانات أو حفظ للصوت أو التفريغ، ولا تسجيل للمحتوى في الشيفرة. قد تبقى ملفات مؤقتة إذا توقفت العملية بالقوة أو توقف نظام التشغيل؛ نظف مساحة الملفات المؤقتة دوريا. ينتقل التسجيل والعينات إلى OpenAI، ثم ينتقل التفريغ والأسماء المطابقة إلى نموذج إعداد المحضر. يرسل `store:false` لطلب Responses؛ قواعد الاحتفاظ بالبيانات لدى المزود تبقى خاضعة لإعدادات حسابك وسياساته. تأكد من موافقة المشاركين واعرض إشعار الإرسال قبل التحليل.

رموز الأخطاء: `401` رمز وصول غير صالح؛ `413` حجم زائد؛ `422` بيانات أو صوت غير صالحين؛ `502` تعذر اتصال الخدمة أو نتيجة مزود غير صالحة. لا تعاد رسائل المزود الخام التي قد تكشف معلومات حساسة. لا تعاد محاولة آلية قد تضاعف تكلفة طلب مدفوع؛ يمكن للمستخدم المحاولة مجددا بعد التحقق من المشكلة.

## التحقق

```bash
python -m unittest discover -s tests -v
python -m compileall -q app tests
```

تستخدم الاختبارات M4A حقيقيا مولدا بـFFmpeg للتحقق من مسار الرفع وفحص الصوت، و`httpx.MockTransport` عند حدود خدمة OpenAI. لا تحتاج إلى مفاتيح فعلية ولا ترسل صوتا إلى الشبكة. تشمل المصادقة ونقص الإعدادات وحجم الطلب والوسائط التالفة وأسماء العينات والمتحدث الجديد وإسناد الأدلة ونتائج المزود التالفة. لا تقيس هذه الاختبارات جودة التعرف على العربية أو بصمة الصوت؛ ذلك يحتاج تجربة حقيقية بملفات وافق أصحابها على استخدامها وحساب مزود فعال.

عقد الخدمة مستند إلى تعريفات SDK الرسمية التي روجعت أثناء بناء النموذج: [طلب التفريغ](https://github.com/openai/openai-python/blob/main/src/openai/types/audio/transcription_create_params.py)، [مقطع فصل المتحدثين](https://github.com/openai/openai-python/blob/main/src/openai/types/audio/transcription_diarized_segment.py)، [دليل التفريغ الصوتي](https://developers.openai.com/api/docs/guides/speech-to-text).
