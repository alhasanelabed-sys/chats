# ربط أجهزة البصمة (SpeedFace‑V5L وغيرها)

## 1. قبل البدء

* الخادم والجهاز على نفس الشبكة، أو يوجد توجيه بينهما (مثال من إعدادك: الجهاز `10.28.65.254` والخادم `10.0.0.34`).
* يُفضّل **IP ثابت للخادم** — الجهاز يتصل بالخادم وليس العكس، لذلك لا يهم إن كان الجهاز على DHCP.
* شغّل `firewall.bat` كمسؤول مرة واحدة (يفتح 8090 و 8081 و 90).
* البرنامج مستقل تماماً: لا يحتاج أي برنامج آخر ولا أي مكتبة SDK. إن كان على الحاسوب برنامج آخر يحجز المنفذ 90 فأوقفه أو استخدم 8081.
* المنفذ **4370** على الجهاز يجب أن يكون مفتوحاً (هو مفتوح افتراضياً) ليعمل الاكتشاف التلقائي والقراءة المباشرة.

## 2. إعداد الجهاز

**القائمة ← COMM. ← Cloud Server Setting** (في بعض الإصدارات: *ADMS*):

| الإعداد | القيمة |
|---|---|
| Server Mode | ADMS |
| Enable Domain Name | OFF |
| Server Address | IP الخادم |
| Server Port | 90 أو 8081 (أو منفذ الواجهة 8090 — كل المنافذ تقبل الأجهزة) |
| Enable Proxy Server | OFF |
| HTTPS | OFF |

ثم من **System ← Date Time** تأكد أن المنطقة الزمنية صحيحة، أو استخدم «مزامنة الوقت» من البرنامج.

> ملاحظة: **Comm Key** (مفتاح الاتصال) و **TCP COMM Port 4370** لا علاقة لهما بـ ADMS؛ يُستخدمان فقط
> لسحب البيانات القديم عبر TCP (زر «سحب الحركات عبر TCP 4370» في البرنامج).

## 3. ماذا يحدث عند أول اتصال

1. الجهاز يطلب `GET /iclock/cdata?SN=...&options=all` فيرد الخادم بكتلة الإعدادات
   (`ATTLOGStamp`, `Delay`, `TransFlag`, `TimeZone`, `Realtime`, `MultiBioDataSupport`...).
2. الجهاز يرسل معلوماته (`table=options`): الطراز، البرنامج الثابت، عدد المستخدمين والوجوه والبصمات،
   وإصدارات خوارزميات الوجه/البصمة/الكف.
3. الخادم يُضيف الجهاز تلقائياً إلى **المنطقة الافتراضية** ويضع في طابوره:
   * إرسال كل موظفي المنطقة (مع قوالبهم) إلى الجهاز،
   * طلب قائمة المستخدمين الموجودين على الجهاز لاستيرادهم.
4. الجهاز يرفع سجلات الحضور القديمة ثم كل بصمة جديدة فور حدوثها (`Realtime=1`).
5. كل 10 ثوانٍ يرسل الجهاز `getrequest` ويستلم الأوامر المنتظرة وينفذها ويرد بالنتيجة (`devicecmd`).

كل ذلك يظهر حيّاً في **الأجهزة ← مراقبة الاتصال**.

## 4. حل المشاكل

| العَرَض | السبب / الحل |
|---|---|
| الجهاز لا يظهر أبداً، ولا شيء في «مراقبة الاتصال» | الشبكة أو الجدار الناري أو عنوان/منفذ خاطئ على الجهاز. من حاسوب آخر افتح `http://IP-الخادم:90/iclock/ping` يجب أن يظهر `OK`. |
| يظهر «UNKNOWN DEVICE» في مراقبة الاتصال | خيار «إضافة الأجهزة الجديدة تلقائياً» معطل — فعّله من الإعدادات أو أضف الجهاز برقمه التسلسلي. |
| الجهاز متصل لكن الموظفون لا يُرسلون إليه | الجهاز بلا منطقة، أو الموظف ليس في منطقة الجهاز. |
| الأوامر تبقى «أُرسل» ولا تصبح «نُفذ» | الجهاز استلمها ولم يرد (انقطاع/إعادة تشغيل). تعاد أوامر القراءة الآمنة تلقائياً؛ أما الحذف وإعادة التشغيل ومسح البيانات فتتوقف وتحتاج إعادة يدوية حتى لا يتكرر أثرها. |
| وقت البصمات منزاح بساعات | اضبط المنطقة الزمنية للجهاز من تعديل الجهاز أو من الإعدادات العامة، ثم «مزامنة الوقت». |
| القالب لا ينتقل من جهاز لآخر | الجهازان بخوارزميتين مختلفتين؛ يُرسل البرنامج صورة الوجه بدلاً من القالب. للبصمة يجب تسجيلها على الجهاز الآخر. |
| أريد إعادة سحب كل شيء من الجهاز | الأجهزة ← نقل البيانات ← «إعادة رفع كل البيانات من الجهاز» (المكرر يُتجاهل). |

## 5. أوامر ADMS المستخدمة

| العملية في البرنامج | الأمر المرسل |
|---|---|
| إضافة/تعديل موظف | `DATA UPDATE USERINFO PIN=..\tName=..\tPri=..\tPasswd=..\tCard=..` |
| حذف/استقالة | `DATA DELETE USERINFO PIN=..` |
| قالب وجه/بصمة/كف | `DATA UPDATE BIODATA Pin=..\tNo=..\tType=9\tMajorVer=..\tTmp=..` (أو `FINGERTMP` للأجهزة القديمة) |
| صورة الموظف / صورة الوجه | `DATA UPDATE USERPIC` / `DATA UPDATE BIOPHOTO` |
| سحب الحركات لفترة | `DATA QUERY ATTLOG StartTime=..\tEndTime=..` |
| سحب المستخدمين والقوالب | `DATA QUERY tablename=user,fielddesc=*,filter=*` |
| مزامنة الوقت | `SET OPTION DateTime=<device time>` |
| تسجيل عن بعد | `ENROLL_BIO TYPE=9\tPIN=..` / `ENROLL_FP PIN=..\tFID=..` |
| أخرى | `INFO`, `CHECK`, `REBOOT`, `CLEAR LOG`, `CLEAR PHOTO`, `CLEAR DATA` |

أنواع BIODATA: 1 بصمة إصبع، 2 وجه (أشعة تحت حمراء)، 7 وريد الإصبع، 8 كف، 9 وجه مرئي (SpeedFace).

## 5.5 المنافذ الثلاثة — لا تخلط بينها

| المنفذ | أين يُضبط | الاتجاه | يستخدمه |
|---|---|---|---|
| **90** (عندكم) | على الجهاز: Cloud Server ← Server Port | الجهاز ← يتصل بـ ← الخادم | ADMS/Push — البرنامج الآخر وهذا البرنامج |
| **4370** | على الجهاز: TCP COMM Port | الخادم ← يتصل بـ ← الجهاز | SDK/سحب مباشر (زر «سحب الحركات عبر TCP 4370») |
| **8090** | على الخادم | المتصفح ← الخادم | واجهة هذا البرنامج |

## 6. الاكتشاف التلقائي: الجهاز يظهر وحده بدون إضافة

**لا تحتاج كتابة أي شيء:** كل جهاز يتصل بهذا الحاسوب (مثلاً ببرنامج حضور آخر على `10.0.0.34:90`) يراه البرنامج من اتصالات
الحاسوب نفسها خلال دقيقة، فيضيفه ويقرأه عبر 4370 — مهما كانت شبكته. الخطوات التالية للأجهزة التي لا تتصل بالحاسوب فقط.

البرنامج يبحث في الشبكة عن أجهزة البصمة بنفسه (كل 30 دقيقة، وبعد دقيقة من التشغيل) ويضيفها تلقائياً،
**بدون أي تغيير على الجهاز**:

1. **الأجهزة ← الجهاز ← «بحث عن الأجهزة»**. اترك الشبكة فارغة (= شبكة هذا الحاسوب) أو اكتب شبكة الأجهزة،
   مثلاً `10.28.65.0/24` أو مدى `10.28.65.200-10.28.65.254` (يمكن كتابة أكثر من شبكة مفصولة بفواصل).
2. خلال ثوانٍ يظهر كل جهاز برقمه التسلسلي وطرازه وعلامة **4370**، ويقرأ البرنامج منه فوراً:
   المستخدمين، البطاقات، **البصمات**، **الوجوه (الأشعة تحت الحمراء)**، وكل **سجلات الحضور**.
3. إن كان على الجهاز مفتاح اتصال (Comm Key) فاكتبه في **إعدادات النظام ← مفاتيح الاتصال المجربة** (مثلاً `0, 123456`).
4. جهاز معروف عنوانه؟ «إضافة بعنوان IP» يضيفه ويقرأه مباشرة.

البحث يعمل على المنفذ 4370 (UDP ثم TCP)، ولا يحتاج أن يكون الجهاز موجّهاً إلى هذا الخادم.

## 7. الاتصال المباشر (4370) أو ADMS — وما الفرق

| | **مباشر 4370** (علامة 4370) | **ADMS / Push** |
|---|---|---|
| من يتصل بمن | البرنامج ← الجهاز | الجهاز ← البرنامج |
| يحتاج تعديل على الجهاز | لا | Cloud Server Setting (أو زر «توجيه الجهاز إلى هذا الخادم») |
| المستخدمون والبطاقات وكلمات المرور | قراءة وكتابة | قراءة وكتابة |
| البصمات | قراءة وكتابة | قراءة وكتابة |
| الوجه بالأشعة تحت الحمراء (Face 7) | قراءة | قراءة وكتابة |
| الوجه المرئي (SpeedFace) والكف وصور التسجيل | ✗ (الجهاز لا يسلّمها عبر 4370) | قراءة وكتابة |
| سجلات الحضور | كل بضع دقائق (الإعداد) | لحظياً |
| الوقت، إعادة التشغيل، حذف السجلات | فوراً | عند الاتصال التالي |

**لنقل كل البيانات الحيوية (الوجه المرئي والكف) :** حدّد الجهاز ← قائمة الجهاز ←
**«توجيه الجهاز إلى هذا الخادم (ADMS)»**. يعرض البرنامج أين يرسل الجهاز الآن (مثلاً `WebServerIP=10.0.0.5 · WebServerPort=90`)،
ويقترح عنوان هذا الحاسوب ومنفذ ADMS، ثم يكتبه في الجهاز ويعيد تشغيله — بدون الذهاب إلى الجهاز. بعدها يتحول الجهاز
وحده إلى ADMS (تختفي علامة 4370) ويرفع كل ما عليه. بعض البرامج الثابتة لا تسمح بتغيير هذا الإعداد عن بعد؛
عندها يُضبط من الجهاز كما في القسم 2.

كل ما يُعدَّل في البرنامج (موظف جديد، بطاقة، نقل منطقة، استقالة، بصمة) يُرسل إلى أجهزة المنطقة بالطريقتين:
أجهزة ADMS عند اتصالها، والأجهزة المباشرة خلال دقيقة (أو فوراً عند الضغط على أي إجراء).

## 7.5 العمل بجانب برنامج حضور آخر بدون أن يشعر أحد

الأجهزة تبقى على `10.0.0.34:90` مرسلة إلى البرنامج الآخر، والموظفون يعملون كالمعتاد. هذا البرنامج يعمل على 8090/8081
و**يقرأ** الأجهزة مباشرة عبر 4370 (بحث عن الأجهزة) كل بضع دقائق: المستخدمون، البطاقات، البصمات، وجوه الأشعة
تحت الحمراء، وكل الحركات — دون أن يتغير شيء على الجهاز أو في البرنامج الآخر.

* «الكتابة على الأجهزة» **مطفأة افتراضياً** (إعدادات النظام)، ولا يكفي امتلاك المنفذ 90 لتفعيلها. فعّل `tcp.write_back` صراحةً بعد مراجعة السعات والمناطق.
* لا تستخدم أزرار الكتابة (مزامنة البيانات إلى الجهاز، حذف، إعادة تشغيل) في هذه الفترة.
* يوم الاستبدال: أوقف البرنامج الآخر (`free_port90.bat`)، فيأخذ البرنامج المنفذ 90 خلال 10 ثوانٍ وتتصل به الأجهزة دون أي تغيير
  عليها، وترفع كل ما عليها عبر ADMS بما فيه الوجه المرئي والكف. ثم فعّل «الكتابة على الأجهزة».

## 7.6 الوضعان التلقائيان (بدون أي إعداد)

| المنفذ 90 | الوضع | ما يعمل |
|---|---|---|
| مشغول ببرنامج آخر | **قراءة فقط** 👁 | قراءة الأجهزة عبر 4370؛ أزرار الكتابة على الأجهزة معطلة ولا يُرسل لها شيء |
| متاح | **اتصال كامل** ✓ | يأخذه البرنامج خلال 10 ثوانٍ وتتصل به الأجهزة (ADMS)؛ الكتابة تحتاج إذن `tcp.write_back` صريحاً |

* أوقفت البرنامج الآخر؟ ينتقل البرنامج للوضع الكامل وحده. صفحة الأجهزة تعرض الوضع الحالي.
* تريد إعادة تشغيل البرنامج الآخر؟ صفحة الأجهزة ← «تحرير المنفذ 90» ثم شغّل البرنامج الآخر، فيعود البرنامج للقراءة فقط.
  وبعد إيقاف البرنامج الآخر مجدداً اضغط «استخدام المنفذ 90 عند توفره».

## 8. الانتقال إلى هذا البرنامج (أجهزة عليها بيانات)

البيانات الموجودة على الأجهزة (المستخدمون، الوجوه، البصمات، الكف، البطاقات، كل سجلات الحضور) **تنتقل تلقائياً**:
عند أول اتصال يرد الخادم بـ `ATTLOGStamp=None` و `OPERLOGStamp=None` فيرفع الجهاز كل ما عليه.

1. «بحث عن الأجهزة» (القسم 6) يقرأ كل ما على الأجهزة فوراً. ثم «توجيه الجهاز إلى هذا الخادم» (القسم 7)
   لتنتقل الوجوه المرئية والكف أيضاً. إن كان برنامج آخر يحجز المنفذ 90 فأوقفه أو وجّه الأجهزة إلى 8081.
2. الأجهزة تُضاف تلقائياً إلى المنطقة الافتراضية. غيّر اسمها (مثلاً «غزة») من الموظفين ← المناطق.
3. انتظر حتى تختفي الأسهم الخضراء (⇈) في صفحة الجهاز: عندها انتهى تبادل البيانات بين الأجهزة.
4. أنشئ الأقسام وانقل الموظفين إليها (إجراءات ← نقل إلى قسم)، أو استورد ملف Excel.
5. عرّف أوقات الدوام والورديات وجدولة الأقسام.

ما لا يأتي من الأجهزة (يُعاد إدخاله أو يُستورد): الأقسام، المسميات، الجداول، الإجازات.

## 9. كيف تعمل المزامنة في الاتجاهين

| الحدث | ما يفعله الخادم |
|---|---|
| موظف جديد/معدّل في البرنامج | `USERINFO` (+ الصورة + القوالب) لكل أجهزة مناطقه |
| نقل موظف إلى منطقة أخرى | إرساله لأجهزة المنطقة الجديدة وحذفه من أجهزة القديمة |
| استقالة/حذف | `DATA DELETE USERINFO` من كل أجهزته |
| مستخدم جديد أو بطاقة/كلمة مرور/صلاحية تغيّرت على جهاز | يُحفظ، ثم يُنسخ لباقي أجهزة المنطقة |
| وجه/بصمة/كف سُجّل على جهاز | يُحفظ، ثم يُرسل (المستخدم أولاً ثم القالب) للأجهزة المتوافقة؛ غير المتوافقة تستلم صورة الوجه |
| صورة موظف من جهاز | تُحفظ وتُنسخ لباقي الأجهزة |
| جهاز يعيد رفع بيانات لم تتغير | لا شيء — لا يحدث تكرار ولا حلقات |
| جهاز غير مسجل (الإضافة التلقائية معطلة) أو معطل | يُرفض الرفع (403) فيحتفظ الجهاز بسجلاته ويعيد المحاولة بعد الموافقة عليه |
| أجهزة iClock قديمة (`/iclock/cdata.aspx`) | مدعومة |
| أجهزة قديمة بدون BIODATA | تستلم `FINGERTMP`/`FACE` بدلاً منه |

> ملاحظة عن «مزامنة الوقت»: يُرسل `SET OPTION DateTime=`؛ بعض إصدارات البرامج الثابتة لا تدعمه وتضبط الوقت من
> الخادم عند الاتصال (مع `TimeZone`). نتيجة الأمر تظهر في «أوامر الأجهزة».
