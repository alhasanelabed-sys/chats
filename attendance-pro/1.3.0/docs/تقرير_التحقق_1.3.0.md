# تقرير التحقق من حاضر 1.3.0

يضيف هذا الإصدار صفحة **النظام ← التشغيل التجريبي** لإنشاء بيانات اصطناعية والتحقق من الأداء والحسابات دون تغيير سجلات الحضور الفعلية. اختر الموظفين والأجهزة والأيام وعدد تكرارات القياس، أو استخدم إعداداً جاهزاً لاحتياج 10,000 موظف و20 جهازاً و30 يوماً.

## السلوك والإعدادات

- تُنشأ قاعدة مستقلة في عملية فرعية؛ لا تستخدم التجربة عناوين أجهزة حقيقية أو الاكتشاف أو كتابة القوالب.
- خيار «إيقاف الكتابة على أجهزة التشغيل أثناء التجربة» محدد افتراضياً؛ يحفظ `tcp.write_back=false` في البرنامج الرئيسي عند قبول التشغيل، ويتركه مطفأً بعد الانتهاء. إزالة العلامة تترك القيمة الحالية كما هي ولا تفعّل الكتابة.
- تعرض الصفحة التقدم، أعداد السجلات، أزمنة التقارير، عينة الموظفين والحضور، ونتائج التصدير وإعادة الإرسال. يمكن تنزيل JSON وCSV المختار، وإلغاء المهمة وحذف نتائجها.
- تعمل تجربة واحدة في الوقت نفسه، مع عشر نتائج محفوظة كحد أقصى ومليوني حركة للتجربة. تتوقف المهمة بعد 20 دقيقة حتى إن غادر المستخدم الصفحة. يغلق العامل عند فقد قناة مالك العملية، وتُنظّف الملفات المؤقتة عند إعادة تشغيل الخادم.
- تُحذف قاعدة التجربة وكلمة المرور المؤقتة؛ يحتفظ البرنامج بالنتيجة والعينة وCSV المختار فقط. يوجد اعتماد `httpx` ضمن متطلبات التشغيل وفحص الإصلاح التلقائي في ويندوز.

دليل الخطوات متاح في [README](../README.md#التشغيل-التجريبي-من-الواجهة). [صورة الواجهة العربية](verification/trial-interface-ar.png) · [صورة الهاتف](verification/trial-interface-mobile.png).

## الاختبارات النهائية

نجحت **330 اختبارات** بالأمر `python -m pytest -q tests --tb=short`، رمز الخروج صفر، في 95.47 ثانية. اكتمل التشغيل في `2026-10-10T08:52:03.732691+00:00`. بقيت بصمة ملفات البرنامج والاختبارات والواجهة ومتطلبات التشغيل متطابقة قبل التشغيل وبعده:

```
b5a45c903c61bbc42381681cdd071bbb251808e98988beb1a2061fe7bf0b616d
```

تشمل الاختبارات الجديدة صلاحية مدير النظام، رفض الخيارات غير الصحيحة، الحد الأقصى، منع التشغيل المتزامن، عزل البيانات، الإلغاء والإيقاف، فشل إنشاء العملية، التنزيل، انقطاع قناة العامل، انتهاء المدة دون استعلامات من الواجهة، وتنظيف الملفات بعد الانقطاع مع إعادة المحاولة عند قفل مؤقت في ويندوز. اختُبر القفل بالتمثيل البرمجي؛ هذا لا يُعد تشغيل ويندوز أصلياً.

نجح تجميع ملفات Python وفحص بنية ملفات JavaScript الخمسة. ظهر تحذير تقادم من Starlette بشأن TestClient/httpx؛ لم يفشل اختبار بسببه. لا يُغيّر هذا الإصدار مكتبات المشروع لمجرد إخفاء التحذير.

أدلة: [نتيجة الاختبارات](verification/tests-1.3.0.json) · [البيئة](verification/environment-1.3.0.json).

## اختبار الحجم عبر واجهة التجارب البرمجية

شُغّلت المهمة من API المدير بنفس الخيارات المستخدمة في الصفحة: **10,000 موظف، 20 جهازاً محاكياً، 30 يوماً، 600,000 حركة وثلاثة قياسات للتقارير**. نجح العامل خلال 44.12 ثانية على Linux وPython 3.12.14؛ شمل فحص التنزيل والحذف 45.20 ثانية.

| التقرير | إجمالي النتائج | وسيط زمن صفحة 200 صف |
|---|---:|---:|
| الحركات | 600,000 | 0.198 ثانية |
| الملخص | 10,000 | 0.708 ثانية |
| اليومي | 300,000 | 0.041 ثانية |

جرى فحص جميع صفوف CSV البالغ عددها **600,001 مع العنوان**، بحجم 42,767,339 بايت، ثم تنزيل الملف فعلياً من مسار API. نجحت 20 طلبات محاكاة متزامنة أعادت إرسال 20,000 حركة، وبقي العدد 600,000 دون تكرار. بقيت سجلات الموظف والجهاز والحركة الموجودة في قاعدة التشغيل الأصلية كما هي، وظل إعداد الكتابة مطفأً. حُذفت قاعدة التجربة وكلمة مرورها، ثم حُذفت نتائج المهمة من API بنجاح.

أدلة: [نتيجة العامل](verification/scale-1.3.0.json) · [تحقق API والتنزيل والعزل](verification/experiment-scale-1.3.0.json).

## اختبار المتصفح الحقيقي

نجح تسجيل الدخول والتنقل إلى الصفحة بواسطة Chromium متصل بخادم Uvicorn محلي وقاعدة معزولة. أنتجت تجربة 20 موظفاً وجهازين ويومين **80 حركة و40 نتيجة يومية**. نُزّل CSV فعلياً بـ81 صفاً وJSON صالح. جرى إلغاء عامل حقيقي وحذف المهمة وملفاتها، وفحص الاتجاه العربي والإنجليزي وعرض الهاتف بعرض 390 بكسل. لم تظهر أخطاء JavaScript.

تطابقت بصمة جميع أعمدة الموظف والحركة والجهاز الأصلية قبل التجربة وبعدها. ظل إعداد الكتابة مطفأً بعد تجربة ثانية مع إزالة علامة الخيار. أُغلق خادم الاختبار وحُذفت قاعدته. [دليل المتصفح](verification/browser-1.3.0.json).

## نتيجة ويندوز الواردة من المستخدم وحدود القياس

أرسل المستخدم نتيجة ناجحة للإصدار **1.2.0** على Windows 11 وPython 3.13.15 وأربعة معالجات منطقية: 600,000 حركة في **247.96 ثانية**، وتصدير CSV في 50.98 ثانية، وأزمنة صفحات وسطية 0.794 للحركات و2.516 للملخص و0.141 ثانية لليومي. أول قياس للملخص استغرق 13.35 ثانية. نجحت إعادة إرسال 20,000 حركة عبر عشرين طلباً متزامناً دون تكرار. [ملخص الدليل الوارد من المستخدم](verification/windows-user-reported-1.2.0.json).

هذه نتيجة قدمها المستخدم للإصدار السابق، وليست اختباراً مستقلاً للنسخة 1.3.0 على ويندوز. تختلف السرعات باختلاف الجهاز والنظام والقرص. أزمنة التقارير تقيس حساب الصفحة داخل الخادم، ومحاكاة الاستقبال تستخدم TestClient ولا تقيس شبكة المؤسسة أو Firmware.

**لم تُختبر الأجهزة الفعلية في هذه الجلسة.** يبقى نطاق التطبيق الحضور؛ يلزم قبول ميداني لأجهزة ZKTeco SpeedFace V5L وسعاتها وإعادة الاتصال قبل الاعتماد. راجع [دليل تشغيل 10,000 موظف](دليل_تشغيل_10000_موظف.md). تؤخذ نسخة احتياطية قبل تحديث تثبيت قائم، وتُحفظ بيانات المؤسسة في مسارها الحالي.
