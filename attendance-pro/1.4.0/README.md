# حاضر 1.4.0 — المراقبة والتقارير والتجربة المرئية

[تنزيل البرنامج مباشرةً (ZIP)](https://raw.githubusercontent.com/alhasanelabed-sys/chats/codex/attendance-1.4.0/attendance-pro/1.4.0/iug-attendance-pro-1.4.0.zip) · [بصمة SHA-256](iug-attendance-pro-1.4.0.zip.sha256) · [المصدر الكامل](source/)

## التشغيل

1. استخرج ZIP كاملاً وافتح `desktop.bat` داخل مجلد `iug-attendance-pro` لنافذة تطبيق عبر Edge/Chrome، أو `start.bat` للمتصفح. يحتاج التثبيت الأول إنترنت لتثبيت Python والمكتبات.
2. للتثبيت الجديد، كلمة مرور `admin` الأولية في `initial_admin_password.txt` داخل مجلد البيانات. غيّرها عند الدخول.
3. افتح **الإعدادات ← التوقيت** وحدد منطقة المؤسسة. اترك **الكتابة على الأجهزة** مطفأة للحضور فقط، واستكمال القوالب عند استقبال حركات مطفأً ما لم تحتاجه.
4. لتجربة الصفحات بموظفين وأجهزة افتراضية، افتح **النظام ← تجربة البرنامج ببيانات افتراضية**، وأدخل الأعداد، ثم افتح رابط البيئة عند جاهزيتها. النسخة مستقلة على منفذ آخر، مع قاعدة وجلسة منفصلتين وحظر الاتصال بالأجهزة الفعلية.

قبل ترقية تثبيت قائم: خذ نسخة احتياطية وأوقف الخادم السابق، ثم استعمل ملفات البرنامج الجديدة مع مجلد البيانات الحالي. لا تنسخ بيانات التجربة فوق بيانات المؤسسة.

## أبرز التغييرات

- المراقبة تعرض جميع حركات اليوم حسب توقيت المؤسسة، مع صفحات وبحث وصور صغيرة. شرح الحضور يوضح الفرق بين الحركة الخام والحساب اليومي.
- الطباعة تشمل جميع النتائج المطابقة للفلاتر، بعمودي أو أفقي، مع تقسيم الأعمدة الواسعة وتكرار هوية الموظف. تصدير CSV/Excel في الخلفية مع التقدم والإلغاء.
- أسماء إجراءات الأجهزة توضح الاتجاه والبيانات: الجهاز إلى الخادم، الخادم إلى الجهاز، أو المصدر عبر الخادم إلى أجهزة أخرى.
- إعدادات مجمعة وبحث، وواجهة تتكيف مع نافذة Windows الضيقة وتنقل سفلي وعناصر للمس.
- قواعد حضور بتاريخ تطبيق وسبب تغيير، وتفسير الحركات المستخدمة والمستبعدة؛ أرشفة دفعات الحضور والمرفوضات وإعادة معالجة دون اتصال بالأجهزة.
- صحة التشغيل والتوقيت والتحقق المعزول من النسخ، واختيار متانة SQLite؛ تحسين الحساب التاريخي والاستقبال المتزامن.

## التحقق

نجحت **440 اختباراً** على المصدر النهائي، وفحص متصفح عربي وإنجليزي بعرض 390px، والطباعة الكاملة والتصدير والتنزيل وعزل التجربة. نجح تشغيل الحزمة المستخرجة نفسها، وفحص CRC وبصمات جميع ملفاتها. تتوفر الأدلة في التقرير وفي `docs/verification`.

نجح اختبار سنة لـ**10,000 موظف و20 جهازاً محاكياً و7,300,000 حركة**، ثم استقبال 20,000 حركة جديدة بالتزامن مع ستة تقارير خلال 2.554 ثانية للمجموعة، وإعادة رفعها دون تكرار. التجربة المرئية الفعلية لـ10,000 موظف و20 جهازاً و30 يوماً أصبحت جاهزة في 15.698 ثانية، وبقيت بيانات التشغيل الرئيسي وإعداد الكتابة كما كانت.

هذه اختبارات Linux ومحاكاة HTTP؛ لم يُشغّل الإصدار على Windows أصلي أو أجهزة SpeedFace V5L فعلية هنا. نافذة `desktop.bat` تعتمد Edge/Chrome. تبقى تجربة Windows والطابعة والربط الميداني والنسخ والاستعادة مطلوبة قبل الاعتماد؛ لا ندعي تقييماً مطلقاً «10/10».
