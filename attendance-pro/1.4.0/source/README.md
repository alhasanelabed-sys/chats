والجداول** مع الإجازات والعطل والعمل الإضافي، ويُخرج التقارير إلى Excel.

## التشغيل السريع (ويندوز)

1. انقر مرتين على **`start.bat`** — في المرة الأولى يثبّت Python وكل المكتبات تلقائياً (يحتاج إنترنت مرة واحدة) ثم يفتح المتصفح.
   لفتح واجهة في نافذة تطبيق مستقلة عبر Edge أو Chrome، شغّل **`desktop.bat`**. تستعمل بيانات الخادم نفسها. الواجهة تتكيف مع حجم النافذة، مع تنقل سفلي عند تصغيرها وأزرار مناسبة للمس.
2. ادخل بـ **admin** وكلمة المرور الموجودة في `initial_admin_password.txt` داخل مجلد البيانات، ثم غيّرها فوراً.
3. (مرة واحدة، كمسؤول) شغّل **`firewall.bat`** لفتح المنافذ، و **`autostart.bat`** ليعمل الخادم تلقائياً مع ويندوز.

| ما هو | العنوان / المنفذ |
|---|---|
| واجهة البرنامج | `http://IP-الخادم:8090` |
| بوابة الموظف (فقط) | `http://IP-الخادم:8091` — المنفذ الوحيد الذي يُفتح على الإنترنت |
| استقبال الأجهزة (ADMS) | `90` و `8081` (قابل للتغيير في `hader.ini`) |
| الاتصال المباشر بالأجهزة | المنفذ `4370` على الجهاز |
| البيانات (قاعدة البيانات، الصور، النسخ الاحتياطية) | `C:\ProgramData\Hader` — تبقى كما هي عند تنزيل نسخة جديدة |

على لينكس: `pip install -r requirements.txt` ثم `python run.py` (البيانات في مجلد `data` بجانب البرنامج).

## الأجهزة تظهر وحدها

لا حاجة لإضافة الأجهزة يدوياً:

* **كل جهاز يتصل بهذا الحاسوب** (على المنفذ 90 أو 8081) يظهر خلال دقيقة، مهما كانت شبكته.
* **«بحث عن الأجهزة»** في صفحة الأجهزة يجد أجهزة البصمة في الشبكة عبر المنفذ 4370، ويقرأ منها فوراً.
* **«إضافة بعنوان IP»** لجهاز معروف عنوانه، و **«إضافة»** برقمه التسلسلي لجهاز مطفأ حالياً.
* إن كان على الأجهزة مفتاح اتصال (Comm Key) فاكتبه مرة واحدة في: إعدادات النظام ← «مفاتيح الاتصال المجربة».

### الاتصال وإذن الكتابة

| المنفذ 90 على هذا الحاسوب | الاتصال | ما يعمل |
|---|---|---|
| مشغول ببرنامج آخر | قراءة مباشرة عبر 4370 | قراءة الحضور إذا كان الجهاز يسمح بالاتصال؛ يمكن استخدام منفذ ADMS الآخر إذا ضُبط الجهاز عليه |
| متاح | استقبال ADMS مع القراءة المباشرة | يستطيع الجهاز إرسال الحضور إلى البرنامج على المنفذ 90 |

**الكتابة إلى الأجهزة مطفأة افتراضياً.** تحتاج كل عمليات الكتابة عبر TCP أو ADMS إلى تفعيل «الكتابة على الأجهزة» (`tcp.write_back`) صراحةً بعد مراجعة المناطق والسعات. امتلاك المنفذ 90 أو تحريره لا يمنح إذن الكتابة. تقبل واجهة الإعدادات قيمة منطقية فعلية (`true` أو `false`) لهذا الإذن.

* لتحرير المنفذ 90 من برنامج آخر: **`free_port90.bat`** (كمسؤول).
* لإعادته إلى البرنامج الآخر: صفحة الأجهزة ← «تحرير المنفذ 90»، ثم «استخدام المنفذ 90 عند توفره» لاسترجاعه.

### ما يُقرأ من الأجهزة

| | الاتصال المباشر (4370) | الجهاز يتصل بالبرنامج (90 / ADMS) |
|---|---|---|
| الحالة والأعداد (مستخدمون، بصمات، وجوه، كف، سجلات) | كل دقيقة | لحظياً |
| المستخدمون والبطاقات والأسماء العربية | ✓ | ✓ (الاسم الكامل) |
| البصمات | قراءة وكتابة بإذن | قراءة وكتابة بإذن |
| وجه الأشعة تحت الحمراء | قراءة | قراءة وكتابة بإذن |
| الوجه المرئي والكف وصور التسجيل | — | قراءة وكتابة بإذن |
| سجلات الحضور | مقارنة كاملة مع قاعدة البيانات كل قراءة | لحظياً |
| التسجيل عن بعد (بصمة/وجه/كف) | — | ✓ بإذن الكتابة، مع متابعة الخطوات |
| سحب البصمات والوجوه والكف وصور الوجه عند الطلب | ✓ (بصمات ووجه الأشعة) | ✓ للجهاز كله أو لموظف واحد، مع شريط تقدم |

كل سجل يُفحص قبل قبوله (رقم موظف صالح وتاريخ معقول)، والسجل التالف يُهمل دون أن يؤثر على ما بعده. تحفظ سجلات التشخيص الخام بصلاحيات مقيدة واسم يتضمن بصمة الملف.

### إعداد الجهاز يدوياً (عند الحاجة)

من الجهاز: **القائمة ← الاتصال (COMM.) ← إعدادات الخادم السحابي (Cloud Server Setting)**:

| الإعداد | القيمة |
|---|---|
| Server Mode | **ADMS** |
| Enable Domain Name | إيقاف |
| Server Address | عنوان IP لحاسوب الخادم (مثال: `10.0.0.34`) |
| Server Port | `90` (أو `8081`) |
| Enable Proxy Server / HTTPS | إيقاف |

أو من البرنامج بدون الذهاب إلى الجهاز: حدد الجهاز ← قائمة الجهاز ← **«توجيه الجهاز إلى هذا الخادم»**.

التفاصيل وحل المشاكل: [docs/ربط_الأجهزة.md](docs/ربط_الأجهزة.md).

## التشغيل التجريبي من الواجهة

من حساب له صلاحية إدارة النظام، افتح **النظام ← التشغيل التجريبي**:

1. اختر **«تجربة سريعة»** (50 موظفاً، جهازان، 7 أيام)، أو **«10,000 موظف · 20 جهازاً»** (30 يوماً، 600,000 حركة). يمكنك تعديل عدد الموظفين والأجهزة والأيام وتكرار قياس التقارير؛ تعرض الصفحة عدد الحركات المتوقع قبل البدء.
2. اختر **تصدير الحركات إلى CSV والتحقق منها** للحصول على ملف قابل للتنزيل، و**محاكاة استقبال متزامن من الأجهزة** لفحص إعادة الإرسال ومنع التكرار. كلا الخيارين مفعّل افتراضياً.
3. اترك **«إيقاف الكتابة على أجهزة التشغيل أثناء التجربة»** محدداً، ثم اضغط **«ابدأ التجربة»**. تابع مراحل الإنشاء والتقارير والتصدير والمحاكاة، أو أوقف التجربة من الصفحة عند الحاجة.
4. عند النجاح، راجع أعداد الحركات وأزمنة التقارير ونتائج التحقق وعينة الموظفين والحضور اليومي. نزّل تقرير JSON، وملف CSV إذا اخترت تصديره. تبقى النتائج في «التجارب السابقة»، ويمكن حذفها من الصفحة.

تنشأ بيانات التجربة في قاعدة مؤقتة مستقلة؛ لا تضاف إلى الموظفين أو سجلات الحضور الفعلية، ولا تتصل التجربة بأجهزة حقيقية. لكل موظف دخول وخروج يومياً في دوام 08:00–16:00، مع تأخير 15 دقيقة لكل موظف رقمه من مضاعفات 20 للتحقق من الحساب. تحذف القاعدة المؤقتة وكلمة مرورها بعد الانتهاء، وتحتفظ الصفحة بالنتائج والعينة وملف CSV المختار فقط.

خيار **إيقاف الكتابة** مفعّل افتراضياً: عند بدء التجربة يحفظ إعداد البرنامج الرئيسي `tcp.write_back=false`، ويتركه مطفأً بعد الانتهاء. إزالة علامة الخيار تترك إعداد البرنامج الحالي كما هو؛ لا تفعّل الكتابة. الكتابة والاكتشاف والاتصال المباشر في بيئة التجربة نفسها تبقى معطلة دائماً.

يسمح البرنامج بتجربة واحدة في الوقت نفسه، وحفظ عشر تجارب، وبحد أقصى مليوني حركة لكل تجربة. يتوقف التشغيل إذا تجاوز 20 دقيقة. قد تستغرق التجربة الكبيرة عدة دقائق وتستهلك موارد الحاسوب مؤقتاً؛ ابدأ بالتجربة السريعة. نجاحها يقيس حسابات البرنامج والتصدير والاستقبال المحاكى؛ توافق أجهزة SpeedFace V5L الفعلية وسعاتها ما زال يحتاج اختباراً ميدانياً.

## كيف يعمل (باختصار)

* **المناطق**: كل جهاز في منطقة، وكل موظف في منطقة أو أكثر. عند تفعيل إذن الكتابة، إضافة موظف أو تعديله أو نقله أو استقالته
  تصل تلقائياً إلى أجهزة منطقته، وما يُسجَّل على جهاز (مستخدم، بصمة، وجه، كف) يُنقل إلى باقي أجهزة المنطقة.
  بعد كل قراءة مباشرة يقارن البرنامج محتوى الجهاز بموظفي منطقته ويرسل الناقص فقط.
* **القوالب**: تُرسل إلى الجهاز إذا كانت خوارزميته متوافقة؛ وإلا تُرسل **صورة الوجه** ليستخرج الجهاز قالبه بنفسه.
* **الحضور يُحسب لحظياً** من البيانات الخام: أي بصمة متأخرة الرفع أو تعديل في الجدول أو اعتماد إجازة
  يظهر فوراً في التقارير — لا يوجد زر «احسب» يُنسى.
* **لا تكرار**: الحركة نفسها لا تُحفظ مرتين مهما أُعيد إرسالها أو قراءتها.

## مدير الخادم (Service Manager)

نافذة سطح مكتب صغيرة على حاسوب الخادم — **`manager.bat`** (أو اختصار «مدير خادم حاضر» على سطح المكتب) — تعمل حتى
لو كان الخادم متوقفاً أو لا يُفتح من المتصفح:

* حالة الخادم وروابطه، و**تشغيل / إيقاف / إعادة تشغيل**، وفتح البرنامج.
* **عنوان IP ومنافذ** الواجهة والبوابة والأجهزة ← «حفظ وتطبيق» (إعادة تشغيل فورية؛ وإن تعذّر الفتح يبقى على السابق).
* **التشغيل التلقائي مع ويندوز** (قبل تسجيل الدخول)، نسخة احتياطية فورية، مجلد البيانات، سجل الخادم
  (`logs\hader.log` في مجلد البيانات)، فتح المنافذ في الجدار الناري، استعادة كلمة مرور المدير، اختصار سطح المكتب.
* عربي وإنجليزي، ويطلب صلاحيات المسؤول مرة واحدة عند فتحه.

يتواصل مع الخادم من هذا الحاسوب فقط وبمفتاح مشتق من مجلد البيانات، فلا يستطيع أحد آخر في الشبكة إيقافه.

### التحديث بنقرة

تبويب **«التحديثات»** في مدير الخادم: «البحث عن تحديث» يعرض ما تغيّر، و«تحديث الآن» ينزّل النسخة الجديدة ويثبّتها:
نسخة احتياطية من البرنامج الحالي ← إيقاف الخادم ← وضع الملفات الجديدة ← تثبيت أي مكتبة جديدة ← تشغيل الخادم والتأكد أنه
يعمل. **إن لم تعمل النسخة الجديدة تُعاد السابقة تلقائياً.** مجلد البيانات (قاعدة البيانات، الصور، الإعدادات) لا يُلمس أبداً.

* المستودع خاص، فيحتاج التحديث **مفتاح قراءة فقط** من GitHub يُدخل مرة واحدة في التبويب نفسه
  (Fine-grained token ← المستودع iug-attendance-pro فقط ← Contents: Read-only).
* **بدون إنترنت:** «تحديث من ملف ZIP…» لنسخة نُزّلت على جهاز آخر (أو `update.bat file.zip`).
* عند فتح المدير يتحقق بهدوء من وجود تحديث ويُنبّهك.

## عنوان الخادم والمنافذ — من داخل البرنامج

**إعدادات النظام ← عنوان الخادم والمنافذ**: عنوان IP الذي يستمع عليه الخادم (كل الشبكات أو بطاقة شبكة محددة)،
ومنفذ الواجهة، ومنفذ بوابة الموظف، ومنافذ استقبال الأجهزة. عند الحفظ يعيد البرنامج تشغيل نفسه على القيم الجديدة خلال
ثانية دون إغلاقه، وتنتقل الصفحة للعنوان الجديد؛ وإن تعذّر فتح العنوان أو المنفذ يعود للقيم السابقة تلقائياً ويعرض السبب.
تُحفظ في `network.ini` داخل مجلد البيانات (فتبقى عند تنزيل نسخة جديدة)، ويفتح البرنامج منافذه في جدار الحماية بنفسه
عندما يعمل كمسؤول (مهمة التشغيل التلقائي).

**من يفتح واجهة الإدارة؟** (في الصفحة نفسها): أي جهاز / أجهزة محددة (عناوين، نطاقات، شبكات) / هذا الحاسوب فقط.
الأجهزة وبوابة الموظف لا تتأثر، وهذا الحاسوب مسموح دائماً.

### النسخ والاستعادة الآمنة

النسخة الاحتياطية من صفحة النظام ملف ZIP متسق يتضمن قاعدة البيانات والصور و`network.ini` ومفتاح الخادم، مع بصمات تحقق. لا تتضمن السجلات أو كلمات المرور المؤقتة. طلب الاستعادة يجهّز النسخة أولاً، ثم يوقف الخادم ويُنشئ نسخة `before_restore` قبل استبدال الملفات. يستخدم مسار قاعدة البيانات المهيأ، حتى إذا كان خارج مجلد البيانات، ويجهّز كل بديل بجوار هدفه لدعم اختلاف أقراص ويندوز. يسجل خطوات الاستعادة لاسترجاع البيانات السابقة عند الفشل أو انقطاع العملية؛ إذا تعذّر إكمال الاسترجاع يتوقف بدء الخادم لحماية البيانات، ويُسجّل السبب في `restore.log`. لا تُجرى استعادة قاعدة البيانات أثناء استقبال الطلبات. اختبر الاستعادة في نسخة منفصلة قبل استخدامها على بيانات المؤسسة.

لأجهزة SpeedFace V5L يُنصح بقراءة قيم السعة قبل تفعيل الكتابة؛ يرفض البرنامج مزامنة تتجاوز `MaxUserCount` أو `MaxFingerCount` أو `MaxFaceCount`، ويعرض سبب الرفض بدلاً من إنشاء طابور جزئي. يمكن أيضاً تحديد شبكات ADMS المسموح بها لكل جهاز، وتظل القائمة الفارغة متوافقة مع DHCP.

## بوابة الموظف

يدخل كل موظف من جواله ليرى دوامه اليوم وسجلّه الشهري وأرصدة إجازاته، ويرسل طلبات الإجازة وتصحيح البصمة
والعمل الإضافي، ويستلم إشعارات التأخير والغياب والرد على طلباته. تُثبَّت كتطبيق من «إضافة إلى الشاشة الرئيسية».

1. **الملف الشخصي ← بوابة الموظف**: رابط الموظفين ورمز QR، و«إصدار كلمات مرور لكل الموظفين» (تُطبع بطاقات فيها
   الرقم وكلمة المرور ورمز QR، أو تُنزل CSV). كل موظف يغيّر كلمة مروره في أول دخول.
2. **داخل المؤسسة**: يكفي اتصال الجوال بشبكة المؤسسة وفتح `http://IP-الخادم:8091`.
3. **من البيت (الإنترنت)**: شغّل **`portal_internet.bat`**:
   * `1` رابط مؤقت فوري للتجربة (`https://….trycloudflare.com`) بدون حساب.
   * `2` رابط دائم باسم نطاقكم وبشهادة HTTPS عبر نفق Cloudflare مجاني (يعمل كخدمة مع ويندوز، بدون تعديل الراوتر).
   ثم اكتب الرابط في صفحة «بوابة الموظف» ليظهر على البطاقات ورمز QR.

**الأمان:** المنفذ 8091 لا يخدم إلا البوابة — صفحات الإدارة وواجهتها البرمجية واستقبال الأجهزة غير موجودة عليه أصلاً —
لذا هو وحده ما يُفتح للإنترنت. كل موظف يرى بياناته فقط؛ الدخول يُقفل بعد 5 محاولات خاطئة للرقم أو 20 من العنوان نفسه
خلال 10 دقائق؛ الجلسة `HttpOnly` و`Secure` عبر HTTPS، مع ترويسات حماية (CSP، منع التضمين، HSTS). لتغيير المنفذ:
**إعدادات النظام ← عنوان الخادم والمنافذ** (أو `run.py --portal 8091`، و`0` لإيقافه).

## English summary

A self-contained time & attendance server for biometric terminals — no third-party server and no SDK.

* **Terminals register themselves**: any terminal talking to this PC is picked up within a minute, and
  *Search devices* finds terminals on the LAN over port 4370.
* **Connection and write permission are separate**: direct reads use port 4370; ADMS uploads use a
  configured listening port. Device writes are disabled by default and require an explicit boolean
  `tcp.write_back=true` setting for both transports, regardless of port 90 ownership.
* **Direct link (`hader/terminal`)**: our own implementation of the 4370 protocol (TCP/UDP, comm key) —
  device info and counters, users with Arabic names, fingerprints, near-infrared faces and punches,
  with record validation; users and fingerprint writes require the explicit write permission.
* **ADMS server** (`/iclock/cdata`, `getrequest`, `devicecmd`, `querydata`, `rtdata`, `registry`):
  users, fingerprint/face/palm templates and photos are distributed per **area**; remote enrollment
  with live progress.
* Attendance is calculated on the fly from timetables, cyclic shifts, department/temporary schedules,
  holidays, leave, manual punches and overtime (with approval); 13 reports export to Excel/CSV.
  Arabic/English UI, roles & permissions, audit log, automatic backups.
* **System → Trial runs** configures synthetic employee/device/day counts, CSV validation and concurrent
  upload simulation in an isolated temporary database, with progress, previews and downloadable results.
  The default option saves production `tcp.write_back=false` and leaves it off afterward; unchecking
  preserves the existing setting. Trial devices never contact physical terminals.

Quick start: `pip install -r requirements.txt && python run.py` → `http://localhost:8090`; the first random admin password is stored in `initial_admin_password.txt` in the data folder and must be changed at first sign-in.

Version 1.2.0 improves concurrent ADMS ingestion, report pagination, bounded CSV/XLSX exports and
offline restore recovery. `tools/benchmark_scale.py` checks 10,000 synthetic employees, 20 simulated
terminals and 600,000 punches in an isolated temporary database. Linux benchmark results do not
replace validation on physical SpeedFace V5L terminals or on the deployment's Windows server.
