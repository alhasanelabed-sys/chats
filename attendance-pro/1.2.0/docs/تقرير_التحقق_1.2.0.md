# تقرير التحقق من حاضر 1.2.0

أُنجزت التحسينات لاحتياج 10,000 موظف و20 جهاز ZKTeco SpeedFace V5L لتسجيل الحضور. هذه نسخة محسّنة ومختبرة برمجياً؛ لم يحدث اتصال بالأجهزة الفعلية، ولم يُنفذ تشغيل على ويندوز في هذه الجلسة. لا تُمنح درجة 10/10 دون قبول ميداني وفق [دليل التشغيل](دليل_تشغيل_10000_موظف.md).

## ما تغيّر

| المجال | التحسين | دليل الاختبار |
|---|---|---|
| استقبال الأجهزة | تصحيح نص إقرار ADMS، ورفض المصادر غير المسموح بها؛ إدراج الموظف والحركات مرة واحدة حتى مع طلبين متزامنين | `test_release_regressions.py`، `test_ingestion_concurrency.py`، `test_adms.py` |
| تحديث التقارير | نشر حدث الحضور بعد نجاح الحفظ، وإسقاطه عند التراجع؛ تحديث الاتجاه التاريخي بعد رفع حركات قديمة ولوحة المؤشرات بعد تعديل البيانات | `test_commit_events.py`، `test_release_regressions.py` |
| أداء التقارير | حساب أيام الصفحة المطلوبة وتحميل موظفيها فقط، مع مراعاة فترة الخدمة والبحث وحدود الصفحات | `test_release_regressions.py`، `test_engine.py` واختبار الحجم |
| التصدير | قراءة الحركات على دفعات، وكتابة CSV وExcel دون تجميع كل الصفوف؛ تطابق المحتوى مع التقارير وتنظيف الملفات عند فشل الإرسال | `test_report_streaming.py` وفحص CSV كاملاً في اختبار الحجم |
| النسخ والاستعادة | قاعدة البيانات في المسار المهيأ، وتجهيز بجوار كل هدف؛ سجل خطوات متين، وتراجع قابل للاستئناف، ومعالجة WAL، وحماية النسخ القديمة أيضاً | `test_recovery.py`، `test_startup_recovery.py`؛ انقطاع حقيقي لعملية فرعية |
| إذن الأجهزة | الكتابة تتطلب قيمة منطقية صريحة، وفحص السعات المعروفة قبل المزامنة وعدم إعادة الأوامر المدمرة تلقائياً | `test_device_safety.py`، `test_release_regressions.py` |
| حسابات الحضور والاعتماد | تغطية الورديات الليلية، ومرساة الدورة، والإجازة والغياب الجزئي، ومنع الاعتماد دون صلاحية | `test_hr_regressions.py`، `test_hr_api_regressions.py` |

تتضمن الحزمة أيضاً تحسينات الإصدار السابق على كلمات المرور والصلاحيات والواجهة. لا تحتوي بيانات المؤسسة أو قاعدة الاختبار أو كلمات المرور الأولية أو ملفات الإعداد السرية.

## نتائج الاختبارات النهائية

* اكتمل التشغيل في `2026-10-09T19:05:02.241730+00:00`.
* الأمر: `python -m pytest -q tests --tb=short`.
* النتيجة: **281 اختباراً ناجحاً**، رمز الخروج صفر؛ استغرق التشغيل 81.59 ثانية.
* بصمة ملفات Python وJavaScript قبل التشغيل وبعده متطابقة: `a401755ab8df7b4117dbfa9c41f32cc1cef64ab27f6e7927d0f87b53fc00dddc`.
* فحص تجميع ملفات Python وبنية ملفات JavaScript الأربعة: ناجح.
* ظهر تحذير تقادم في تكامل Starlette TestClient مع httpx؛ لا يوجد فشل اختبار بسببه. تفاصيل المكتبات المختبرة في [ملف البيئة](verification/environment-1.2.0.json).

## اختبار الحجم النهائي

الأمر المستقل القابل للتكرار:

```bash
python tools/benchmark_scale.py --employees 10000 --devices 20 --days 30 --repeat 3 --export --ingestion --output scale.json
```

أنشأ الاختبار بيانات اصطناعية في قاعدة مؤقتة مستقلة: **10,000 موظفاً، 20 جهازاً محاكياً، 30 يوماً و600,000 حركة**. تعطلت قراءة الأجهزة الفعلية والاكتشاف والكتابة خلاله. تحقق من الصفحات الأولى والأخيرة وعينات الحسابات، وحذف قاعدة البيانات وCSV عند انتهاء العملية.

| التقرير | النتائج الكلية | وسيط زمن صفحة 200 صف، من 3 قياسات |
|---|---:|---:|
| الحضور اليومي | 300,000 | 0.042 ثانية |
| الملخص | 10,000 | 0.673 ثانية |
| الحركات | 600,000 | 0.187 ثانية |

* صدّر **600,001 صف CSV مع العنوان**، بحجم 42,767,339 بايت، في 25.55 ثانية. فُحص كل صف على حدة للتأكد من الرقم والوقت والحالة والجهاز وترتيب الحركات.
* أعاد **20 طلب ADMS متزامناً** إرسال 20,000 حركة موجودة. نجحت الردود كلها، وبقي عدد الحركات 600,000 دون تكرار.
* استغرق اختبار الحجم كله 44.23 ثانية على Linux-6.18.44-x86_64-with-glibc2.41 وPython 3.12.14؛ عدد المعالجات المتاحة للاختبار 3.

أرقام الصفحات تقيس بناء التقرير داخل الخادم بقاعدة SQLite المحلية، ولا تشمل شبكة المؤسسة والمتصفح. اختبار الطلبات المتزامنة استخدم TestClient؛ لا يحاكي زمن الشبكة أو Firmware. التصدير الكبير المقاس CSV؛ اختُبرت صحة Excel في اختبارات أصغر، ولم يُقَس تصدير 600,000 حركة إلى Excel.

النتائج التفصيلية: [اختبارات الإصدار](verification/tests-1.2.0.json) و[اختبار الحجم](verification/scale-1.2.0.json).

## القبول الميداني وحدود الإصدار

يلزم اختبار الأجهزة الـ20 مع إصدارات Firmware الفعلية، وسعات المستخدمين والوجوه والبصمات، وعودة الحركات بعد انقطاع الشبكة، وتطابق عينة الدوام مع الحساب اليدوي. يلزم أيضاً تشغيل ويندوز وتجربة الاستعادة على أقراص ومسارات الخادم المقصود. نجاح محاكي الأجهزة لا يثبت التوافق الميداني.

النسخ الاحتياطي يدعم قواعد SQLite الملفية ذات المسارات العادية المطلقة والنسبية. قواعد الذاكرة وSQLite URI وقواعد غير SQLite غير مدعومة بهذه الآلية، ويُرفض التعامل معها صراحةً. يبقى نطاق هذه النسخة الحضور؛ لا توجد اختبارات اعتماد رواتب أو خصومات.

ابدأ بإذن الكتابة مطفأ، ثم نفذ [خطوات التشغيل والقبول](دليل_تشغيل_10000_موظف.md). يحتوي `RELEASE_MANIFEST.json` داخل ZIP على بصمة كل ملف لتأكيد سلامة الحزمة؛ يتوفر ملف SHA-256 منفصل للتحقق من ZIP نفسه.
